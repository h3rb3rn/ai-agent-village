# P17.1 – Neo4j host recovery

Date: 2026-09-26

## Scope

Restore the Neo4j graph backend on N06-M10 and reconnect the existing
projection worker without restarting agent services.

## Findings

The container had exited with code 137 during the host reboot sequence. The
host journal shows the normal system shutdown path and Neo4j logged
`Server shutdown initiated by request`; `OOMKilled` was false and the host had
ample free memory after boot. Exit 137 therefore reflects the final forced
termination during shutdown, not a Neo4j data or memory failure. The
persistent `/data` mount and graph state were retained.

The operational gap was boot orchestration: the projection worker started
before the stopped Podman containers were brought back, and the compose
`restart: unless-stopped` policy alone did not restore this explicitly stopped
container after the reboot.

## Recovery

The existing container was started in place (no image pull and no data reset),
then the projection worker was restarted. Neo4j exposed HTTP 7474 and Bolt
7687. The worker reported:

```text
backends=['chroma', 'neo4j']
neo4j: last_sequence_id=84, lag=0, error_count=0, status=active
```

An authenticated read-only Cypher health query returned 140 nodes and 136
relationships with no errors. Chroma remained active at the same time.

## Verification class

`HOST_VERIFIED` on N06-M10. No agent unit was restarted.
