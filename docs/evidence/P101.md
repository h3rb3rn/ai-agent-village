# P101 – Verworfene Themen kommen nur mit Begründung zurück

## Trigger

> "ja, für alle drei von 101 bis 103"

## Befund (HOST_VERIFIED, 2026-10-09)

- Am 8. Oktober wurden 63 verwaiste Tasks auf `abandoned` gesetzt. Am 9. Oktober legten Methodologist und Artisan wieder Tasks zum selben Thema an: „Disk monitoring script with proper log cleanup“ und „Extend disk-monitor with log rotation and alerting“.
- P96 ließ verworfene Tasks bewusst aus dem Doppelschutz heraus. Damit war das Wiederanlegen ohne jede Hürde möglich.

## Änderung

`village/coordinator.py`, Anlage eines Tasks:
- Passt das Thema (gleicher Titel oder Themenwort-Vergleich wie in P96) zu einem verworfenen Task, wird die Anlage abgelehnt.
- Die Fehlermeldung nennt den verworfenen Task und verlangt das Feld `new_because` mit mindestens 40 Zeichen, also was sich seither geändert hat.
- Mit `new_because` wird der neue Task angelegt wie bisher.

## Tests (LOCAL_VERIFIED)

- `tests/test_coordinator.py`: `test_abandoned_topic_needs_a_stated_reason_to_come_back`. Der Test schlägt gegen den alten Code fehl.
- Der Test aus P96 (`test_abandoned_projects_neither_block_nor_count_towards_the_limit`) wurde angepasst: Die Neuanlage eines verworfenen Titels braucht jetzt eine Begründung.
- Gesamte Suite: siehe Commit.

## Offen

- Die Begründung wird nicht inhaltlich geprüft, nur die Länge. Ein Agent kann einen Satz schreiben, der nichts ändert. Das wäre ein eigener Schritt.
