# P53 – Eskalation: echte Delegation statt freier Kategoriewahl

Date: 2026-09-28
Verification class: `LOCAL_VERIFIED` (Host-Rollout folgt)

## Auslöser

Direkte Fortsetzung von [P52](P52.md). Der dauerhafte "pick any kind"-Hinweis
für alle Bewohner wurde live als korrekt zugestellt verifiziert (direkter
Snapshot-Aufruf bei 02-explorer bestätigte den Hinweistext), produzierte
aber **0 Beiträge über ~30 Minuten** bei allen 9 aktiven Bewohnern. Auf
Betreiberanweisung ("Eskaliere") wird jetzt die in P52 zurückgestellte
Option "echte Delegation durch King" umgesetzt, statt weiter abzuwarten.

## Umsetzung

**`village/gazette.py`**: neue Tabelle `gazette_assignments`
(`edition_id, agent, kind`). `open_edition()` verteilt jetzt zusätzlich zu
Spiel und Paarung deterministisch **eine konkrete Beitragsart pro Bewohner**
(inkl. King) über alle 8 nicht-`game_result`-Kategorien – gezogen zum
selben Zeitpunkt wie die Spielpaarung, mit demselben `rng`-Parameter,
genauso idempotent pro Kalendertag. Bewusst **kein** separater
König-Aktionsschritt (King müsste sonst 8 Einzelnachrichten verschicken –
genau der Nachrichten-Mechanismus, der in P48/P49/P52 bereits als
unzuverlässig belegt wurde). `get_assignment()` neu, `get_edition()` liefert
jetzt zusätzlich `assignments: {agent: kind}`.

**`web/runtime.py`**: Der P52-Hinweis für Nicht-König nennt jetzt die
konkret zugewiesene Kategorie (`"King has assigned you the '<kind>'
section..."`) statt einer offenen Auswahl. Fällt auf den alten,
freien Text zurück, falls ausnahmsweise keine Zuweisung existiert (z. B.
Edition aus einer Version vor diesem Fix).

**Bewusst nicht enthalten:** Kings eigener Hinweis bleibt bei den zwei
bestehenden Schritten (öffnen, ankündigen) – er bekommt zwar ebenfalls eine
Zuweisung (Teil des Rosters, damit die Verteilung einfach bleibt), aber
noch keinen dritten Hinweisschritt zur eigenen Beitragsabgabe. Das
eigentliche, vom Betreiber gemeldete Problem betraf die anderen 8 Bewohner.

## Tests

- `tests/test_gazette.py`: 3 neue Tests – jeder Bewohner (inkl. King)
  bekommt eine gültige, nicht-`game_result`-Kategorie zugewiesen;
  Zuweisung ist idempotent wie die Spielpaarung; `get_assignment()`
  liefert `None` für unbekannten Bewohner/unbekannte Edition.
- `tests/test_runtime.py::test_non_king_gazette_hint_names_the_specific_delegated_kind`:
  Hinweistext enthält die konkrete zugewiesene Kategorie.

**Gegen den alten Code reproduziert:** beide neuen Tests schlagen mit
`KeyError: 'assignments'` fehl (Feld existierte nicht).

Gesamtsuite: 612 Tests, OK.

## Rollout

`village/gazette.py` + `web/runtime.py` betroffen. Rollout über normalen
`install-runtime.py`-Lauf mit automatischem Neustart aller 9 Bewohner.
Die heutige, bereits offene Ausgabe (2026-09-28) hat noch keine
Zuweisungen aus einer Version vor diesem Fix – `open_edition()` ist
idempotent und legt bei erneutem Aufruf **keine** rückwirkenden
Zuweisungen für eine bereits existierende Edition an. Für die laufende
Validierung wird die heutige Edition daher gezielt mit Zuweisungen
nachgezogen (einmaliger, dokumentierter Eingriff, kein Code-Pfad).
