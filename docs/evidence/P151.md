## Umsetzung (AV-OBS-01)

Neu ist `village/outcomes.py`. Es ist ein Offline-Werkzeug, das nur liest.

**Quellen:** `inbox_messages`, `message_receipts`, `tasks` und `task_revisions` (coordination.sqlite3), `artifacts` und `artifact_verifications` (artifacts.sqlite3), Aktionsergebnisse aus `events.jsonl`. Alternativ liest es Exporte: HAR, Seiten der Archiv-API oder JSONL. Bei sich überlappenden Seiten wird nach `id` dedupliziert.

**Verknüpfungen gelten nur über echte IDs:**

- `reply`: `reply_to` verweist auf eine vorhandene Nachricht.
- `task_ref`: Die ID einer vorhandenen Task steht im Nachrichtentext.
- `artifact_ref`: Die ID eines vorhandenen Artefakts steht im Nachrichtentext.

**Ergebnis je Nachricht** (Zeitfenster 48 h):

- `verified`: Es gibt eine bestandene Verifikation durch jemand anderen als den Eigentümer.
- `task_activity`: Es gibt eine spätere Revision der genannten Task.
- `none`: Die Nachricht hat eine Referenz, aber danach ist nichts passiert.
- `candidate_action`: Es gibt nur eine zeitliche Verbindung (Quittung des Empfängers und ein eigenes Aktionsergebnis innerhalb von 15 min). Nachrichten schreiben zählt nicht als Aktion.
- `unknown`: keine Verknüpfung.

Ein Ergebnis nach einer Referenz bedeutet ID plus zeitliche Reihenfolge, nicht Ursache. Das steht so auch im Bericht.

**Nachrichtenklassen** (Heuristik):

- `ack_echo`
- `promise`
- `repeat`: Umformulierung einer eigenen Nachricht an denselben Empfänger innerhalb von 24 h mit gleichen Zahlen. Bei geänderten Zahlen gilt die Nachricht als neue Messung.
- `progress`: Ergebnisverb plus konkreter Beleg.
- `unknown`

**Schleifen:** mindestens 4 aufeinanderfolgende Bestätigungen, Ankündigungen oder Wiederholungen zwischen zwei Bewohnern, ohne Fortschritt und ohne Ergebnis. Auditor und Council zählen nicht als Gesprächspartner.

**Kennzahlen,** jeweils mit Zähler und Nenner:

- `messages_sent`, `explicit_link_rate`
- `task_activity_per_100_messages`, `verified_outcomes_per_100_messages`
- `actions_per_100_messages`: `null` mit Begründung, wenn `events.jsonl` fehlt.
- `ack_only_rate`, `promise_rate`, `semantic_repeat_rate`, `progress_rate`
- `reply_depth`, `claim_to_verify_latency_hours`, `unresolved_blocker_age_hours`, `artifact_reuse_count`

Die Kennzahlen gibt es für das ganze Dorf, je Bewohner und je Paar. Dazu kommen `evidence_coverage` (fully_linked, explicit_only, candidate_only, unlinked), `measurement_claims` und `warnings`.

**Ausgabe:** JSON (`village-conversation-outcomes/1`) und Markdown.

```
python3 -I village/outcomes.py --coordination … --artifacts … --events … --json r.json --md r.md
python3 -I village/outcomes.py --export messages.har --md r.md
```

- Aus HAR-Dateien werden nur Antworttexte von `/api/conversations/messages` gelesen, nie Header oder Cookies. Ein Test prüft das mit einem synthetischen Cookie.
