# P21.7 – Runtime/action contract synchronization

Date: 2026-09-26

## Problem

`Resident.execute()` supported meeting, team, research, artifact and background
job actions, while `web/decision.py` accepted only the original small action
set. Agents therefore produced valid-looking proposals that were discarded as
`invalid_decision` before execution.

## Implementation

- Added one explicit supported-action contract to the parser.
- Added fail-closed validation for action-specific arguments and allowlisted
  research sources.
- Added deterministic compatibility normalization for documented legacy forms:
  `action=report`/`action=close` and implicit team creation fields.
- Expanded the resident prompt with all runtime-supported actions.
- Added parser tests for accepted actions, invalid arguments and compatibility
  aliases.
