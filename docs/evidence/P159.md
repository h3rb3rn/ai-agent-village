# P159: Schulstunde verschwindet nach der eigenen Antwort aus dem Kontext

## Anlass

Der Betreiber hat am 2026-10-13 einen Runtime-Audit beauftragt: Root Cause zu Gates, Werkzeug-Verfügbarkeit und Schleifenbremse; danach nur das erste nachweislich offene Infrastrukturproblem beheben. Die Gap-Analyse steht in `docs/analysis/RUNTIME-AUDIT-2026-10-13.md`.

**Live-Befund** (`/api/observatory`, 2026-10-13 UTC): `01-king` hat die Lektion des Tages fünfmal beantwortet, jedes Mal mit `stored=False`.

```
18:22:49 01-king school_answered agent=01-king; day=2026-10-13; stored=False
18:50:49 … 19:41:35 … 20:01:33 … 20:18:58 (gleich)
```

## Root Cause

- **Versprechen von P117:** „Today's lesson now sits in every resident's context until answered.“
- **Code in `snapshot()`:** setzt `school_lesson` immer, sobald für heute eine Lektion existiert. Ob der Bewohner schon geantwortet hat, prüft er nie; `answers_for()` wurde in der Runtime nirgends aufgerufen.
- **Gleichzeitig:** `record_answer()` nimmt nur eine Antwort pro Bewohner und Tag an (`INSERT OR IGNORE`, Rückgabe `False`).

Die Runtime fordert also weiter „answer it once today“ und lehnt jede weitere Antwort ab. Das ist ein Widerspruch der Infrastruktur, kein Modellfehler.

## Änderung

**`web/runtime.py`, `snapshot()`:** `school_lesson` wird nur noch gesetzt, wenn `self.id` nicht in `answers_for(plan, heute)` steht. Unverändert bleiben:

- der Text der Lektion;
- die Antwortlogik;
- die Bewertung;
- die Rückmeldung an den Bewohner;
- das Ereignis `school_answered`;
- die Lektion für alle anderen Bewohner.

## Tests

`tests/test_school_answered.py` enthält 3 Tests:

1. Die Lektion steht im Snapshot, bis der Bewohner geantwortet hat, danach nicht mehr. **Ohne den Fix schlägt dieser Test fehl** (geprüft durch Rücknahme der Zeile: `FAILED (failures=1)`).
2. Der Live-Fall wird nachgestellt: Eine zweite Antwort wird nicht gespeichert.
3. Andere Bewohner sehen die Lektion weiterhin.

