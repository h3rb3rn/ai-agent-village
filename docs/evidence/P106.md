# P106 – Profil-Pflicht vor Arbeitsaktionen (schaltbar)

## Befund (HOST_VERIFIED, 2026-10-09)

- Nur 05-interpreter hat ein Profil (Stand 17:59 Uhr), obwohl der Kontext jedem Agent ohne Profil die Aufforderung gibt. In den letzten Antworten aller Agents kam `profile_operation` nicht vor.
- Ein Gate, das alle Aktionen außer dem Profil blockiert, brach 36 bestehende Tests. Ein engeres Gate brach weiterhin rund zwanzig Tests, weil Testabläufe Befehle ausführen, ohne Profil.

## Änderung

`web/runtime.py`, `Resident.guard()`:
- Nur mit `VILLAGE_PROFILE_GATE=1` in der Agent-Umgebung.
- Gilt für Arbeitsaktionen (`PROFILE_GATED_ACTIONS`: `execute_bash`, `start_job`, `task_operation`, `team_operation`, `research_request`, `artifact_operation`).
- Ab dem zweiten Zyklus ohne Profil wird die Aktion abgelehnt, mit der Aufforderung zu `profile_operation`. Die Sperre endet, sobald ein Profil existiert.
- Profil-, Kalender-, Gazette- und Meeting-Aktionen sind nie betroffen.
- Standard ist aus: Bestehende Tests und das Verhalten ohne Schalter bleiben unverändert.

## Tests (LOCAL_VERIFIED)

- `tests/test_runtime.py`: `test_profile_gate_refuses_solo_work_after_two_cycles_without_profile`, `test_profile_gate_is_released_once_a_profile_exists`, `test_profile_gate_is_off_by_default`.
- Gesamte Suite: 1176 Tests OK.

## Betrieb

- Aktiviert auf N06-M10 für alle neun Agents (`VILLAGE_PROFILE_GATE=1` in `/etc/ai-village/agents/*.env`). Sicherungen `*.bak-pre-profilegate-<Zeitstempel>`.
- Wirkung zu prüfen: Anzahl Profile und `profile_required_gate`-Ereignisse.
