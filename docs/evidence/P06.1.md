# P06.1 – Versioned scientific event identity

Runtime events now contain `schema_version`, unique `event_id` and a persistent
per-process-generation `run_id`. Existing event readers remain compatible
because the original fields are retained. This makes restart boundaries and
causal event grouping measurable instead of inferred from timestamps.

Verification: event-schema and runtime tests are `LOCAL_VERIFIED`. Host rollout
is a separate intervention and must be recorded with its deployment time.
