# P21.23 – Gedächtnis-Dashboard: Monitoring-Fehler, nicht Realität

Date: 2026-09-27
Verification class: `HOST_VERIFIED`
Anlass: Betreiberfrage „Laut Dashboard ist Gedächtnis-Substrat leer. Monitoring-Fehler
oder Realität?“

## Antwort: Monitoring-Fehler. Die reale Gedächtnisbasis ist nicht leer.

Direkte Prüfung der autoritativen SQLite-Datenbank auf N06-M10
(`/var/lib/ai-village/memory/memory.sqlite3`, root, read-only):

- **290 Erinnerungen**, verteilt über mehrere Agents, aktiv wachsend.
- `projection_states`: `chroma` und `neo4j` beide bei `last_sequence_id=290`,
  `error_count=0`, `status=active` – identisch mit der Outbox-Gesamtzahl (290).
  **Keine Projektionsverzögerung, keine Fehler.**

## Ursache des falschen Dashboard-Bilds

Das Dashboard (`web/observatory.js`, `renderMemory()`) liest ausschließlich
`data.current.memory.stats`, geschrieben von `web/telemetry-collector.py` über
`GET http://127.0.0.1:8090/v1/stats`. Diese Route in `memory/gateway.py` warf bei jedem
Aufruf eine unbehandelte `NameError: name 'projection' is not defined` – die Variable
`projection` wurde referenziert, aber in diesem Routenzweig nie berechnet (nur im
`/v1/memories`-Zweig, wo eine gleichnamige lokale Variable existiert). Die Ausnahme
entstand außerhalb des `try`-Blocks für `sqlite3.OperationalError` und wurde daher nicht
abgefangen, sondern brach die HTTP-Antwort komplett ab – reproduziert live:

```
curl -sv http://127.0.0.1:8090/v1/stats
...
* Empty reply from server
```

`telemetry-collector.py`s eigener `except Exception: result['stats'] = {'agents': [],
'total': 0, 'chars': 0}` fängt den daraus resultierenden Verbindungsfehler ab und trägt
stillschweigend die leeren Platzhalterwerte ein – exakt das, was das Dashboard zeigte.
`/healthz` (unauthentifiziert, ohne den Bug) funktionierte währenddessen fehlerfrei,
weshalb der Gateway-Dienst selbst fälschlich „gesund“ wirkte.

## Umsetzung

Ein-Zeilen-Fix in `memory/gateway.py`, `/v1/stats`-Zweig: `projection =
projection_stats(conn)` wird jetzt berechnet (identisch zum `/v1/memories`-Zweig),
bevor die Verbindung geschlossen wird.

## Tests

`tests/test_memory_gateway.py::MemoryStatsRouteTests` (2 neue Tests, echter HTTP-Aufruf
über `ThreadingHTTPServer`, nicht nur die isolierte `projection_stats()`-Funktion):
1. Gegen den **alten** Code reproduziert: `http.client.RemoteDisconnected: Remote end
   closed connection without response` – exakt das Host-Symptom.
2. Mit dem Fix: `/v1/stats` liefert 200 mit `total`, `agents` und einem vollständigen
   `projection`-Block, auch im Leerfall (0 Erinnerungen).

Die bereits bestehenden `ProjectionStatsTests` (`tests/test_memory_stats.py`) prüften
nur die Hilfsfunktion isoliert und hätten diesen Bug nie gefangen – das war die
eigentliche Testlücke.
