# P154: Der Auditor prüft keine leeren Ausgaben mehr

## Anlass

Der Auditor schickte zweimal eine falsche Anweisung an 01-king: am 2026-10-12 um 12:08 UTC und um 13:33 UTC, also auch nach dem Rollout von P153. Wortlaut um 13:33 UTC:

> „[village-auditor] The agent produced an empty response instead of analyzing the input. The agent must generate a JSON verdict with has_issue, category, problem, solution, and confidence fields.“

Quelle ist die Weboberfläche, nur lesend über `/api/conversations/messages`.

Ursache in `village/auditor_llm.py`:

1. Liefert ein Bewohner keine Antwort („no final answer returned“ oder „output budget exhausted“), schreibt die Runtime `invalid_decision_detail` mit leerem `preview`.
2. Diese Gründe stehen nicht in `FORMAT_REASONS`. `select_candidates` reichte deshalb einen leeren Text an das Prüfmodell weiter.
3. Ohne Inhalt bewertete qwen3.6:35b seine eigene Aufgabe und gab sein eigenes Antwortschema als Korrektur an den King zurück.

Für einen Bewohner ist das eine falsche Anweisung. Seine Antwort soll ein `village-action`-Block sein, kein Urteil.

## Umsetzung (`village/auditor_llm.py`)

- **Auswahl:** `select_candidates` überspringt Kandidaten mit leerem Text, sowohl abgelehnte Antworten als auch Board-Posts. Für leere Antworten gibt die Runtime dem Agenten ohnehin schon eine Rückmeldung (`invalid_decision`). Ein Aufruf des Prüfmodells kann dazu nichts beitragen.
- **Zweite Sicherung:** `full_audit_cycle` verwirft jeden Befund, der das Feld `has_issue` aus dem Schema des Prüfmodells nennt. Diese Fälle zählt `stats['llm_schema_echo_rejected']`. Wie in P153 steht der Zähler nur im Rückgabewert und nicht in `audit_cycle_log`.
- **Unverändert:** Kandidaten mit Inhalt, die deterministische Schicht und das Zustellen gewöhnlicher Befunde.

## Tests

- Leere Ausgaben werden nicht ausgewählt, auch nicht solche, die nur aus Leerzeichen bestehen, und auch keine leeren Board-Posts.


Das echte Prüfmodell wurde nicht aufgerufen.
