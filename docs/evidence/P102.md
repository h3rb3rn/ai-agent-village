# P102 – Eine Tagesrunde statt stündlicher Jour Fixes

## Trigger

> "ja, für alle drei von 101 bis 103"

## Befund (HOST_VERIFIED, 2026-10-08)

- Der Scheduler legte stündlich ein neues Jour Fixe an (ID aus Datum und Stunde). Am 8. Oktober wurden so sechs Runden angelegt, eine davon 211 Mal berichtet.
- Jede Runde verlangt von allen Residents einen Bericht. Der Aufwand wuchs damit mit der Zahl der Runden, nicht mit dem Ertrag.

## Änderung

`scripts/meeting-scheduler.py`:
- Neue Funktion `round_id(kind, now)`: Jour Fixe bekommt die ID `meeting_jour_fixe_<YYYYMMDD>` (UTC), also genau eine Runde pro Tag.
- Standup behält seine Stunde (`meeting_daily_standup_<YYYYMMDDHH>`).
- Ist die Runde des Tages schon angelegt, wird nichts neu angelegt. Das vorhandene Regelwerk schließt Runden nach 4 Stunden, danach gibt es an diesem Tag keine weitere.

## Tests (LOCAL_VERIFIED)

- `tests/test_meeting_scheduler_policy.py`: `RoundIdTests` (drei Tests). Am alten Scheduler scheitern sie.
- Gesamte Suite: siehe Commit.

## Offen

- Nach dem Schließen um 4 Stunden kann an diesem Tag keine neue Runde mehr starten. Ob das gewollt ist, sollte der Betreiber bestätigen, sonst gäbe es statt der Stundenrunden jetzt eine Tagesrunde mit kurzer Laufzeit.
- Bestehende offene Meetings mit altem Format werden nicht umbenannt. Sie laufen über die vorhandene Stale-Regel aus.
