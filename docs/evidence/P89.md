# P89 – Dashboard-Sprachdateien: Englisch (Standard) + Deutsch

## Trigger

> "Im Dachboard ist es irritierend, das die Inhalte auf Englisch, die WebUI aber auf Deutsch ist. Extrahiere alle Labels und Beschreibungen der WebUI in getrennte Language Files und stelle der WebUI die Sprachauswahl Englisch (default) und Deutsch bereit. Lege dafür die notwendigen Sprachdateien an."

Nachgeschärft per Rückfrage (AskUserQuestion):

- Die separate, serverseitig gerenderte Login-Seite (`web/webui.py::login_page()`) wird **nicht** übersetzt ("Nein, nur Dashboard-SPA").
- Die strukturellen Überschriften im kompilierten Gazette-Archiv **sollen** ebenfalls übersetzt werden ("Auch übersetzen").

## Diagnose

Das Dashboard (`web/observatory.html`/`.js`) war durchgehend deutschsprachig fest codiert (Labels, Platzhalter, Tooltips, generierte Textbausteine in ~30 Render-Funktionen), während die von Agenten erzeugten *Inhalte* (Board-Posts, Gazette-Artikel, Status-Notizen) überwiegend englisch sind – ein spürbarer Sprachbruch. Es gab keine Trennung von Text und Code, keine Sprachdateien, keine Sprachauswahl.

## Architektur

- **Neue Sprachdateien** `web/lang/en.json` und `web/lang/de.json`: verschachtelte JSON-Wörterbücher, ein Key-Baum pro Panel/Bereich (`toolbar`, `kpis`, `calendar_panel`, `gazette_panel`, `lab_panel`, `auditor_panel`, `common`, `event_labels`, …), **468 identische Keys** in beiden Dateien (Python-Skript-Diff bestätigt: leere Differenzmenge in beiden Richtungen).
- **`web/observatory.html`**: `lang="de"` → `lang="en"`; jeder statische deutsche Text/Attributwert durch englischen Literaltext **plus** `data-i18n="…"` (bzw. `data-i18n-placeholder`/`-title`/`-aria-label`) ersetzt – der Literaltext selbst ist der Offline-/Vor-Ladezustand-Fallback, das Attribut die Veredelung zur Laufzeit. Neues Toolbar-Steuerelement `<select id="lang">` (Englisch/Deutsch) neben der bestehenden Farbauswahl.
- **`web/observatory.js`** (komplette Neufassung, keine Logikänderung außer der Sprachanbindung):
  - `t(path, vars)`/`L_get(path)`: zentrale Übersetzungs-Lookup-Funktion mit `{platzhalter}`-Ersetzung.
  - **`DEFAULT_LANG`**: eine fest eingebettete Kopie von `en.json`s Inhalt direkt im JS (von Hand synchron zu halten, kein Bundler im Projekt) – garantiert, dass jeder `t()`/`L_get()`-Aufruf echten englischen Text liefert, auch bevor `loadI18n()`s `fetch()` fertig ist, oder wenn er nie fertig wird (offline; insbesondere die bestehenden DOM-freien Node-Testharnesses unter `tests/fixtures/*.js`, die diese Datei nie über HTTP ausliefern, sondern direkt per `vm.runInContext` laden).
  - `loadI18n(code)`: lädt `/assets/lang/<code>.json`, fällt bei Fehlschlag/`code==='en'` auf `DEFAULT_LANG` zurück.
  - `applyI18n()`: läuft über jedes `[data-i18n]`/`[data-i18n-placeholder]`/`[data-i18n-title]`/`[data-i18n-aria-label]`-Element; überspringt ein Element, wenn der Key fehlt (`L_get()` liefert `undefined`), statt mit einem rohen Key-Pfad zu überschreiben – lässt dann den bereits korrekten Literaltext aus dem HTML stehen.
  - Jede der ~30 Render-Funktionen (Board, Kalender, Gazette, Lab, Auditor, Memory, Map, Services, Events, Signals, …) sowie alle Label-Dicts (`CALENDAR_*_LABELS`, `LAB_*_LABELS`, `AUDITOR_CATEGORY_LABELS`, Event-Label-Map) lesen jetzt aus dem geladenen Wörterbuch statt fest codierter deutscher Strings.
  - `setLanguage(code)`: persistiert in `localStorage` (`ai-village-lang`, Default `'en'`), lädt neu, ruft `applyI18n()` **und** rendert alle bereits geladenen dynamischen Panels neu (anders als der reine CSS-Theme-Wechsel).

## Gazette-Archiv zweisprachig (vom Betreiber bestätigt im Scope)

- `village/gazette.py`: neues `GAZETTE_LABELS`-Dict (`"en"`/`"de"`) für ausschließlich **strukturelle** Begriffe (Abschnittsüberschriften, Beitragsarten, Rollen "stellt die Aufgabe"/"antwortet", "Gewinner"/"Unentschieden" usw.) – Beitragsinhalt (was ein Agent tatsächlich geschrieben hat) wird nie übersetzt oder umformuliert, in keiner Sprache. `compile_edition(edition_id, lang=None)` neu parametrisiert, Default `"en"` (passend zum neuen Dashboard-Standard); `lang="de"` reproduziert exakt den Wortlaut, den jede vor diesem Paket bereits archivierte Ausgabe trägt. Alter, flacher `KIND_LABELS`-Name bleibt als Rückwärtskompatibilitäts-Alias auf `GAZETTE_LABELS["de"]["kind"]` erhalten.
- `village/gazette_pdf.py`: `edition_sections()`/`render_edition_pdf()` bekommen dasselbe `lang`-Parameter, nutzen dieselben `GAZETTE_LABELS`.
- `web/runtime.py`s `close`-Dispatch: schreibt pro Ausgabe jetzt **zwei** Archivpaare, jedes einzeln write-once (keine Regression der bestehenden Write-once-Garantie) – `index.html`/`gazette.pdf` (Englisch, Standard) und neu `index.de.html`/`gazette.de.pdf` (Deutsch). Ein Fehler beim deutschen Render verliert nie das bereits geschriebene englische Archiv (eigener try/except, eigenes Event `gazette_de_archive_failed`/`gazette_pdf_de_failed`).
- `web/webui.py`s Archiv-Route: `/gazette/<id>.html`/`.pdf` unverändert (jeder bereits geteilte Link bleibt gültig); neues, optionales `.de.`-Infix (`/gazette/<id>.de.html`, `/gazette/<id>.de.pdf`) für die deutsche Variante, über dieselbe Datums-Regex abgesichert (Traversal-Schutz unverändert wirksam, per Test erweitert geprüft).
- `web/observatory.js`s `renderGazette()`: hängt den `.de.`-Infix an, sobald `LANG_CODE==='de'` ist; Body-Cache jetzt sprachbewusst (`edition.id:LANG_CODE`), damit ein Sprachwechsel neu lädt statt die andere Sprache aus dem Cache zu zeigen. Für Ausgaben, die vor diesem Paket archiviert wurden (keine `.de.`-Geschwisterdatei), fällt der Fetch automatisch auf die einfache `.html`-Datei zurück – die trägt für diese alten Ausgaben ohnehin bereits den ursprünglichen deutschen Text, da Deutsch bis zu diesem Paket die einzige Sprache war.

## Gefundene und behobene Fehler vor Deploy

1. **Absturz bei fehlgeschlagenem Sprach-Fetch**: die vier Node-Testharnesses (`tests/fixtures/*.js`) mocken `fetch` als `Promise.resolve({ok:false})`; `applyI18n()`s `configView[1]` griff dann auf `undefined` zu und riss den gesamten Prozess (unhandled promise rejection) mit nicht-null-Exit-Code ab – 10 Tests schlugen fehl. Fix: `configView`-Zuweisung nur bei vorhandenem Wert, plus die oben beschriebene `DEFAULT_LANG`-Fallback-Ebene.
2. **Fehlende `common.*`/`event_labels.*`-Keys**: beim ersten Entwurf in beiden Sprachdateien schlicht vergessen, obwohl `observatory.js` bereits darauf zugriff – nachträglich ergänzt, Symmetrie erneut per Diff bestätigt.
3. **`&nbsp;`-Entity-Bug** (aus der vorherigen Teilsitzung bereits gefunden): `signals_panel.contact_submit` enthielt den literalen String `"&nbsp;"`, der unter `textContent`-Zuweisung nicht als Leerzeichen interpretiert würde – durch das echte U+00A0-Zeichen ersetzt.
4. **`board_panel.info` (nur `en.json`)**: Schlusstext versehentlich auf `"no selected thread"` verdreht statt `"only recorded agent communication"` – gefunden, weil der Dashboard-Statistik-Test genau diesen Satz erwartete; korrigiert.
5. **`issue_meta`-Vorlage** (Gazette): die deutsche Fassung nutzte ursprünglich die HTML-Entity `&middot;` – im PDF-Kontext (reiner Text, keine Entity-Auflösung) wäre das wörtlich als `&middot;` erschienen. Auf das literale UTF-8-Zeichen `·` vereinheitlicht (Projektkonvention, bereits überall sonst so verwendet).

## Deploy

`web/lang/en.json`/`de.json` bereits in `village/release.py`/`scripts/install-runtime.py` als Install-Ziele erfasst (aus der vorherigen Teilsitzung). Alle übrigen geänderten Dateien (`village/gazette.py`, `village/gazette_pdf.py`, `web/runtime.py`, `web/webui.py`, `web/observatory.{html,js}`) sind bereits bestehende Release-Dateien.

**Wichtig**: Die Simulation war zu Beginn dieser Teilsitzung auf Betreiberauftrag ("Fahre die Simulation parallel herunter, da die Ollama-Instanzen eine neue Container-Version erhalten") bewusst gestoppt (alle 9 Agenten-Systemd-Units gestoppt, Pause-Marker gesetzt). Dieses Deploy betrifft nur Code/Dashboard, keine Inferenzaufrufe – `git pull --ff-only` + `scripts/install-runtime.py` + Neustart des `village-web`-Dienstes sind davon unabhängig und unbedenklich. Die 9 Agenten-Units werden **nicht** neu gestartet, bis der Betreiber die abgeschlossene Ollama-Container-Aktualisierung bestätigt.

## Nachtrag: die zwei vor diesem Paket archivierten Ausgaben manuell auf Englisch nachgezogen

Betreiberauftrag (2026-10-01, nach dem Deploy): "Ziehe die zwei alten Gazette Versionen auf Englisch nach. Übersetze sie selbst."

Betroffen: die beiden einzigen zu diesem Zeitpunkt archivierten Ausgaben, **2026-09-30** und **2026-10-01** – beide vor diesem Deploy kompiliert, also noch ohne `.de.`-Geschwisterdatei und mit deutschen Strukturlabels unter dem Klarnamen `index.html`/`gazette.pdf`.

**Vorab geprüft**: der tatsächliche Beitragsinhalt beider Ausgaben (alle Interviews, Dorfmeldungen, Sitzungszusammenfassungen, die Spiel-Lösung) ist bereits durchgehend englisch verfasst – übrig blieben ausschließlich die festen Strukturlabels (bereits durch `lang="en"` abgedeckt) **und** ein einzelner Freitext-Satz: der gezogene Spielname (`gazette_editions.game_name`), der aus der festen `GAME_POOL`-Konstante in `village/gazette.py` stammt und *nicht* Teil von `GAZETTE_LABELS` ist (das Dict übersetzt nur Strukturlabels, nie Freitext/Inhalt) – dieser eine Satz wurde von Hand übersetzt: "Schaetzfrage zu einem Ressourcenmesswert, der der Wahrheit am naechsten kommt gewinnt" → "Estimation quiz about a resource measurement - whoever's guess comes closest to the truth wins".

**Vorgehen** (zwei befristete, einmalige Hilfsskripte, nicht Teil des Repositories, nach Ausführung vom Host entfernt):

1. Vollständiges Backup vor jeder Mutation: Kopie beider Archivverzeichnisse (`/var/backups/ai-village/gazette-manual-en-backfill-<Stempel>/`) sowie der gesamten `coordination.sqlite3` (`/var/backups/ai-village/coordination.sqlite3.pre-gamename-translate-<Stempel>`).
2. Die bestehenden, deutsch gelabelten `index.html`/`gazette.pdf` wurden **byte-identisch** nach `index.de.html`/`gazette.de.pdf` kopiert – nichts neu gerendert, kein Risiko einer Abweichung vom ursprünglich archivierten Text.
3. Erst danach wurde der Klarname `index.html`/`gazette.pdf` mit einer frischen `compile_edition(edition_id, lang="en")`/`render_edition_pdf(..., lang="en")`-Ausgabe überschrieben – gegen dieselben, bereits genehmigten Beiträge (eine kompilierte Ausgabe nimmt keine neuen Einreichungen mehr an, also kein Drift-Risiko).
4. `gazette_editions.game_name` für beide IDs per `UPDATE` auf die englische Übersetzung gesetzt (dieses Feld ist nicht sprachgetrennt – es fließt sowohl in die Live-API `/api/gazette` als auch in jede künftige Kompilierung ein), danach `index.html`/`gazette.pdf` erneut regeneriert, um die Übersetzung aufzunehmen. `index.de.html`/`gazette.de.pdf` blieben unberührt (bereits vor der DB-Änderung aus den Originalen kopiert) und zeigen weiterhin den ursprünglichen deutschen Satz.
5. Eigentümer/Rechte jeder neu geschriebenen Datei exakt wie das bestehende Muster: `village-king:ai-village`, `0640`.

**Bewusste, einmalig befristete Ausnahme von der Write-once-Garantie**: `web/runtime.py`s automatischer Close-Dispatch rührt ein bereits existierendes Archivfile nie wieder an – diese Garantie gilt unverändert für jede künftige automatische Kompilierung. Hier wurde auf expliziten, konkret benannten Betreiberauftrag hin genau zweimal (für genau diese zwei historischen Dateien) bewusst gegen diese Regel verstoßen, mit vorherigem Vollbackup und ohne jeden Datenverlust (die Originale liegen unverändert unter `.de.` weiter).

**Verifiziert (HOST_VERIFIED)**:
- `GET /gazette/2026-09-30.html` / `/gazette/2026-10-01.html` → `lang="en"`, englische Strukturlabels, englischer Spielname, keine verbleibenden deutschen Zeichen/Wörter (`grep` auf Umlaute und auf `Schaetz|naechsten|Ausgelost|Aufgabe:|Lösung|Dorfmeldungen|Sitzungen|Ausgabe Nr` → leer).
- `GET /gazette/2026-09-30.de.html` / `/gazette/2026-10-01.de.html` → unverändert deutsch, inkl. des ursprünglichen deutschen Spielnamens.
- `GET /gazette/<id>.pdf` beider Ausgaben → enthält den übersetzten Spielnamen als Text.
- `GET /api/gazette` → `game_name` beider Einträge jetzt englisch (erwartete, akzeptierte Nebenwirkung: dieses Feld ist nicht sprachgetrennt).

**Offener, bewusst nicht in diesem Nachtrag behobener Punkt**: `GAME_POOL` in `village/gazette.py` ist weiterhin eine rein deutsche Konstante – jede künftig neu eröffnete Ausgabe zieht wieder einen deutschen Spielnamen, der (anders als die beiden hier manuell nachgezogenen Altausgaben) nicht automatisch übersetzt wird. Der Betreiberauftrag war ausdrücklich auf die zwei bestehenden Altausgaben beschränkt; eine strukturelle Lösung (z. B. `GAME_POOL` selbst zweisprachig wie `GAZETTE_LABELS`) wäre ein eigenes, kleines Work-Package.

## Offene Punkte

- Die separate Login-Seite bleibt bewusst deutsch (Betreiberentscheidung).
- Vor diesem Paket archivierte Gazette-Ausgaben bekommen keine nachträgliche `.de.`-Geschwisterdatei (Write-once-Garantie); ihre einzige, bereits existierende `index.html`/`gazette.pdf`-Datei bleibt – zufällig passend – deutsch, da Deutsch bis zu diesem Paket die einzige Sprache war.
- `DEFAULT_LANG` in `observatory.js` ist eine von Hand gepflegte Kopie von `en.json` – bei künftigen Sprachdatei-Änderungen muss diese Kopie mit aktualisiert werden (kein Bundler/Build-Schritt im Projekt, der das automatisch synchron hielte).
