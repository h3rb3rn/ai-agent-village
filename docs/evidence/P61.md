# P61 – Prüfinstanz von 09-chronicler auf 01-king umgewidmet (Nicht-Compliance trotz korrektem Gate)

Date: 2026-09-29
Verification class: `LOCAL_VERIFIED` (Host-Rollout folgt)

## Auslöser

Beobachtungsfenster nach dem P60-Deploy (Tracker, 40+ Minuten, alle 2–3
Minuten geprüft): Alle 3 Beiträge zur Ausgabe 2026-09-28 blieben
durchgehend `pending`, kein Archiv. Das P60-Gate feuerte nachweislich
korrekt (`gazette_review_gate`-Ereignisse im Stream, Druckzähler
zählte hoch, Blockierungsmeldung enthielt das fertige JSON-Beispiel mit
echter `edition_id`/`agent`/`kind`) – 09-chronicler blieb trotzdem über
32+ aufeinanderfolgende Blockierungen ohne jede einzige `review`-Aktion.
Das ist deutlich mehr als die ~15 Zyklen, die die strukturell identische
Meeting-Gate-Situation bei diesem Agenten zuvor auflösten (P56/P58) –
eine echte, anhaltende Nicht-Befolgung, keine Infrastrukturlücke.

Betreiberentscheidung auf Nachfrage: **"Rolle neu zuweisen"** (statt
"Weiter beobachten" oder "König kompiliert notfalls ohne volle
Prüfung").

## Ursache

`REVIEWER_AGENT` in `village/gazette.py` war fest auf `09-chronicler`
gesetzt (P55, thematisch begründet – "der Historiker"). Über die
gesamte Session hinweg hat aber ausschließlich 01-king jeden
persistenten Hinweis/jedes Gate irgendwann tatsächlich befolgt (Öffnen,
Ankündigen, Zuweisen – P48/P49/P54). Die Wahl fiel damit
evidenzbasiert auf den einzigen bereits erprobten, konform reagierenden
Bewohner statt auf einen ungetesteten Rateversuch.

## Fix

### `village/gazette.py`

- `REVIEWER_AGENT` von `"09-chronicler"` auf `"01-king"` geändert, mit
  Kommentar zur Evidenzbasis (siehe oben).

### `web/runtime.py` – Folgefehler beim Testlauf gefunden

Da King jetzt gleichzeitig Ersteller/Ankündiger/Zuweiser/Schließer
**und** Prüfer ist (beide Rollen sind jetzt dieselbe Identität), war der
bestehende Hinweis-Block in `snapshot()` als sich gegenseitig
ausschließende `if self.id=='01-king': ... else: ...`-Verzweigung
gebaut – korrekt, solange es zwei verschiedene Bewohner waren, aber
jetzt gewann Kings eigener Zweig immer, der Prüf-Hinweis war für ihn
**unerreichbar**.

Behoben durch vollständige Neustrukturierung: `gazette_pending_reviews()`
(P59-Nachtrag, bereits von `guard()` genutzt) wird jetzt zuerst geprüft
und hat Vorrang vor Kings eigenen Tagesaufgaben (Öffnen/Ankündigen/
Zuweisen) – Begründung: ein unbearbeiteter Prüf-Rückstau blockiert die
gesamte kompilierte Ausgabe direkt, während das Öffnen einer neuen
Tagesausgabe jederzeit nachgeholt werden kann, sobald der Rückstau
abgearbeitet ist.

## Tests (`tests/test_runtime.py`)

- `from village.gazette import REVIEWER_AGENT` importiert statt der
  Bewohner-ID fest zu verdrahten.
- `test_gazette_review_is_restricted_to_chronicler` →
  `test_gazette_review_is_restricted_to_the_reviewer` (Assertion prüft
  jetzt `REVIEWER_AGENT` statt der Zeichenkette `"09-chronicler"`).
- `test_chronicler_can_review_and_king_can_close_with_archive` →
  `test_reviewer_can_review_and_king_can_close_with_archive`: auf eine
  einzelne `Resident`-Instanz vereinfacht, da beide Rollen jetzt
  dieselbe Identität sind.
- 6 Vorkommen von `chronicler_env = dict(..., AGENT_ID='09-chronicler', ...)`
  auf `AGENT_ID=REVIEWER_AGENT, AGENT_NAME='king', AGENT_ROLE='king'`
  umgestellt (Variablennamen `chronicler_env`/`chronicler` bewusst
  unverändert gelassen – minimaler Diff, keine inhaltliche Bedeutung
  mehr an den Namen geknüpft).
- 2 Aufrufe von `review_contribution(..., '09-chronicler', ...)` auf
  `REVIEWER_AGENT` umgestellt.
- `test_chronicler_review_hint_survives_a_day_rollover` um eine
  zusätzliche Assertion erweitert
  (`assertNotIn('No AI Village Gazette edition is open for today', ...)`):
  dieser Test konstruiert bereits exakt das Szenario, das die neue
  Prioritätsregel beweist (heute keine Ausgabe offen, aber eine
  ausstehende Prüfung von gestern) – unter dem alten Code hätte
  Kings eigener "Ausgabe heute öffnen"-Hinweis gewonnen und den
  Prüf-Hinweis verdeckt.

**Gegen den alten Code reproduziert:** vor der `snapshot()`-Korrektur
schlug genau diese Assertion fehl (`'editorial review'` fehlte im
Kontext, stattdessen Kings eigener Öffnen-Hinweis).

Gesamtsuite: 680 Tests, OK.
