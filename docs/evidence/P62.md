# P62 – Legacy-JSON-Parser verwirft mehrfache, sauber getrennte Aktionsobjekte komplett

Date: 2026-09-29
Verification class: `LOCAL_VERIFIED` (Host-Rollout folgt)

## Auslöser

Live-Beobachtung direkt nach dem P61-Rollout: 01-king versuchte um
04:36 Uhr als neuer Prüfer aktiv zu reagieren – er bündelte mehrere
Aktionen in einer Antwort, darunter zwei `gazette_operation review`
(je ein Approve für die beiden ausstehenden Beiträge) und
anschließend `gazette_operation close`. Inhaltlich genau das
Richtige. Die Antwort landete jedoch als `invalid_decision_detail`
mit `reason=incomplete legacy action object` – vollständig verworfen.
Sein Prüf-Druckzähler stieg seither ungebremst weiter (5+), ohne dass
je eine Aktion durchkam.

## Ursache

Der Parser (`web/decision.py`) hat für ` ```village-action `-Blöcke
bereits eine Toleranz für mehrere Aktionsblöcke pro Antwort (P51:
"small models frequently narrate a multi-step plan as several
sequential action blocks" – nur der erste wird ausgeführt, der Rest
gezählt und ignoriert). Für den unformatierten/Legacy-Pfad
(`content.startswith('{')`, kein Fence) galt diese Toleranz **nicht**:
`_parse_object()` verwarf die gesamte Antwort, sobald irgendwo nach
dem ersten vollständigen Objekt noch ein `{` auftauchte – exakt das
Muster, das King produzierte (mehrere zeilengetrennte rohe
JSON-Objekte statt Fenced Blocks). Dieselbe Modellneigung wie in P51,
nur in einem Pfad, der die dort bereits gebaute Großzügigkeit nicht
teilte.

## Fix (`web/decision.py`)

- `_parse_object()` gibt jetzt `(obj, extra_object_count)` zurück statt
  nur `obj`.
- Nach dem ersten vollständig geparsten Objekt wird der Rest der
  Antwort untersucht:
  - Kein weiteres `{` vorhanden → unverändertes Verhalten (nachfolgende
    Prosa wird toleriert, `extra=0`).
  - Ein weiteres `{` folgt **unmittelbar nach reinem Leerraum**
    (insbesondere Zeilenumbrüchen) → als sauber getrenntes weiteres
    Aktionsobjekt gewertet, gezählt, aber nicht ausgeführt (dieselbe
    Semantik wie `extra_blocks_ignored` bei Fenced Blocks).
  - Ein weiteres `{` folgt nach **nicht-leerem Text** (z. B. `"...
    then {...}"`) → weiterhin abgelehnt, da hier nicht klar ist, ob
    das erste Objekt allein stehen sollte (bestehender Test
    `test_second_object_after_inline_prose_is_still_rejected` bleibt
    unverändert grün und dokumentiert diese bewusst engere Grenze).
- `decision()` gibt den gezählten Überschuss jetzt genauso wie beim
  Fenced-Block-Pfad über `extra_blocks_ignored` weiter (sichtbar über
  dieselbe Auditor-/Event-Pipeline wie P51).

## Tests (`tests/test_reliability.py`)

- `test_second_object_after_first_is_still_rejected` umbenannt in
  `test_second_object_after_inline_prose_is_still_rejected` (Verhalten
  unverändert, Name beschreibt jetzt präzise, warum dieser Fall
  weiterhin abgelehnt wird).
- Neu: `test_several_newline_separated_legacy_objects_take_the_first` –
  reproduziert das Live-Muster (drei zeilengetrennte rohe
  JSON-Objekte), erwartet Ausführung des ersten und
  `extra_blocks_ignored == 2`.

**Gegen den alten Code reproduziert:** der neue Test schlug vorher mit
`fallback_reason == 'incomplete legacy action object'` fehl statt eine
Aktion auszuführen.

Gesamtsuite: 681 Tests, OK.
