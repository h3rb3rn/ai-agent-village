# P96 – Doppelte Projekte und Projektlimit nach Aufräumen

## Trigger

> "Behebe und setze Regeln" (nach der Bereinigung verwaister Tasks)

## Befund (HOST_VERIFIED, 2026-10-08, N06-M10)

- Vor der Bereinigung gab es 64 offene oder aktive Projekte. Die Bereinigung setzte 63 davon auf `abandoned`, einer blieb aktiv (`Habitat Inventory Script`, heute aktualisiert).
- Die Regel in `CoordinationStore.operate()` zählte aber alle Projekte außer `complete`. Damit blieb das Limit von 64 erreicht, und jede neue Projektanlage schlug mit `64 open projects already exist` fehl. Das war eine Regression durch die Bereinigung.
- Der bisherige Doppelschutz prüfte nur gleiche Titel (ohne Groß-/Kleinschreibung). Die Dubletten hatten aber unterschiedliche Wörter, z. B. `Disk usage monitor script for /mnt/hdd1` und `Create disk monitoring script ...`. Es gab 63 bereinigte Projekte, viele davon zum selben Thema (Disk-Monitor-Skript, Compact-Tool).

## Änderung

`village/coordinator.py`:
- Abgeschlossene und verworfene Projekte (`complete`, `abandoned`) blockieren keine neue Anlage und zählen nicht zum Limit von 64.
- Ähnlicher Titel: Titel werden auf Themenwörter reduziert (generische Verben und Füllwörter entfernt, einfache Endungen entfernt). Zwei Titel gelten als dasselbe Projekt, wenn die Themenmengen mindestens zu 50 % (Jaccard) übereinstimmen. Unterscheiden sich die Wörter in einer Ziffer (z. B. `hdd1` gegen `hdd2`, `000` gegen `001`), gelten sie als verschieden.
- Bei einem Treffer wird das bestehende Projekt zurückgegeben, wie bisher beim exakten Titel.

`tests/test_coordinator.py`:
- `test_abandoned_projects_neither_block_nor_count_towards_the_limit`
- `test_same_topic_under_other_wording_returns_the_existing_project`
- `test_different_topics_stay_separate`

## Offen / nicht Teil dieses Pakets

- Die Regel ist eine Heuristik über Titel. Sie fängt Umformulierungen mit gleichen Themenwörtern. Ganz andere Formulierungen zum selben Thema bleiben unerkannt.
- Der Code ist nicht auf dem Host installiert. Bis dahin bleibt das Limit blockiert, weil die Bereinigung auf dem Host mit dem alten Code läuft.
- Die Änderungen an `village/residents.py` und `tests/test_residents.py` im Hauptcheckout sind nicht Teil von P96 (Batch 96 statt 128). Sie stammen von einer anderen Session und wurden nicht angefasst.
