# P21.8 – Named-peer consultation gate

Date: 2026-09-26

## Scope

Ensure that the collaboration checkpoint for peer consultation cannot be
satisfied by another broadcast to `ALL`.

## Implementation

When the current checkpoint is `consult`, `web/runtime.py` now accepts a
`board_message` only when its `recipient` exactly matches the selected peer.
Broadcasts are rejected with a concrete correction and recorded as
`collaboration_gate`; no false consultation is written to the Board.
