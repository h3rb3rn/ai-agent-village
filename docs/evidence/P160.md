# P160: Observatory trennt verschiedene von wiederholten erfolgreichen Befehlen

## Anlass

Runtime-Audit vom 2026-10-13, Frage 4: Werden erfolgreiche Shell-Ausführungen als fachlicher Erfolg bewertet? Siehe `docs/analysis/RUNTIME-AUDIT-2026-10-13.md`.

Freigabe des Betreibers: „Gebe P160 frei“.

**Live-Befund** (`/api/observatory`, 2026-10-13 18:12–20:26 UTC): `02-explorer` führte 11-mal denselben Befehl `cd /var/lib/ai-village/users/explorer && python3 habitat_inventory.py` aus. Das Observatory zeigte dafür:

- `success` 11, `success_rate` 1.0;
- `capability_index` 90 in der Fähigkeitskurve.

## Root Cause

- **Tasks:** Hier liegt kein Fehler. `task_operation complete` ist eine Selbstauskunft und bleibt mit `completion_verified=0` stehen; `outcomes.py` zählt korrekt nur verifizierte Abschlüsse.
- **Observatory, Ausführungstabelle:** `observer.outcome_stats` zählt jeden Exit-Code 0 als `success`. Das ist dort als „Exitcode-Erfolgsquote“ beschriftet und damit korrekt; dass derselbe Befehl elfmal lief, war aber nur unter „Wiederholte Versuche“ zu sehen.
- **Observatory, Fähigkeitsverlauf:** `webui.skill_history` gewichtet den Anteil erfolgreicher Exit-Codes mit 70 % im `capability_index`. Wiederholungen zählen nur über `escalation` (blockierte Wiederholung), nicht über identische, erfolgreich wiederholte Befehle. Elfmal dasselbe ergibt so den Index 90: Technische Ausführung erscheint als Fähigkeit.

## Änderung

Die Änderung betrifft nur die Betreiber-Ansicht und nie den Kontext der Agenten. Die Runtime liest weder `/api/observatory` noch diese Kennzahlen.

**`web/observer.py`:**

- `result_signature()` normalisiert den Befehl aus `command_result` (`command=…; output=`). Leerzeichen gelten als gleich.
- `outcome_stats` liefert zusätzlich `distinct_success` (jeder erfolgreiche Befehl einmal) und `repeated_success`.
- `success` und `success_rate` bleiben unverändert (Exitcode-Quote).
- Ein Ergebnis ohne Befehl wird nie zusammengelegt.

**`web/webui.py`, `skill_history`:**

- Pro Agent und Stundenfenster wird `distinct_success`/`repeated_success` gezählt.
- `capability_index` nutzt `distinct_success` statt `success`. Wiederholungen verdünnen also den Erfolgsanteil, statt ihn zu heben.
- Der bisherige Index bleibt als `capability_index_exitcode` erhalten, damit die Zeitreihe vergleichbar bleibt.

**`web/observatory.js`, `web/lang/de.json`, `web/lang/en.json`:**

- Ausführungstabelle: „davon N verschiedene Befehle“.
- Tooltip der Fähigkeitskurve: „(N verschieden)“.
- Erklärtext angepasst.
- Ohne neues Backend fällt die Anzeige auf `success` zurück (`??`).
