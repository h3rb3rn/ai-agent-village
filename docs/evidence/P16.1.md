# P16.1 – ChromaDB host recovery

Date: 2026-09-26

## Scope

Recover the ChromaDB runtime after the N06-M10 reboot without changing the
agent configuration or restarting the simulation workers.

## Evidence

`ai-village_chromadb_1` was stopped after the reboot while the persistent data
directory remained present. The container was started with:

```text
sudo podman start ai-village_chromadb_1
```

The Chroma health endpoint returned a heartbeat:

```json
{"nanosecond heartbeat":1790434596388402121}
```

The projection worker was restarted and reported:

```text
Projection worker started: backends=['chroma', 'neo4j']
Projected records: {'chroma': 1, 'neo4j': 0}
chroma: last_sequence_id=84, lag=0, error_count=0, status=active
```

The Neo4j backend remains degraded because its container is separately
unavailable (`connection refused`); this does not prevent Chroma projection.

## Verification class

`HOST_VERIFIED` on N06-M10. Local Chroma/projection tests also pass:

```text
python3 -m unittest tests.test_chroma_adapter tests.test_projection -q
Ran 17 tests in 0.848s
OK
```
